# RSI：生成对抗式自我提升协议（v0.5，2026-10-26）

给定**模型**、**可用训练资源**和**评测平台**，在 RoboDojo（dual X5）上做多轮"生成数据 → 训练 → 对抗评测"的迭代，提高模型的泛化能力。本文件是所有参与这件事的 coding agent 的最高规则；和别的文档冲突时以本文件为准。目标与消融设计见 Notion「生成对抗式 RSI」。

核心思想是课程式学习：数据方像老师，按学生的薄弱科目出课程，循序渐进；评测方像考官，按学生水平调整试卷难度，防止偏科。两方互相对抗，互不通信。

## 一、三条硬规则

### 规则 1：官方评测资产必须保留，生产数据时一律不用

**T0 官方保留资产**（严格口径，用户 10-24 选定），任何训练数据都不许用，包括：
- 出现在 RoboDojo 官方评测布局里的资产。官方有**三套**评测集：`Eval_Layout/RoboDojo/arx_x5/{0,1,2}`，每套都是 54 个任务、2690 个布局，三套都算；
- 没有官方训练数据的任务（12 个 `_random`、8 个开放任务）的配置里**能抽到**的编号，即使评测布局里碰巧没出现（例如 `general_pickup` 的 85 个候选物体、`pack_objects_into_box_random` 的留出实例）。

但官方训练数据本身见过的资产（34 个有数据任务的评测布局和配置里的编号）除外，两方都能用。官方训练数据的场景全是同一房间、同一桌面、没有干扰物。

| 资产 | 官方总数 | T0 | 两方都能用（官方训练见过） | 训练池 / 考场池（7:3） |
| :-- | :-- | :-- | :-- | :-- |
| 房间 `Assets/Room` | 14 | 12（全被 `_random` 用掉） | `Simple_Room`、`Simple_Room_nolight` | 0 / 0 个新房间目录；变体靠换墙面（下面「房间」一行），墙面材质按材质池走 |
| 桌面 / 地面 MDL 材质 | 504 | 494 | 2 种 | 342 / 135（官方剩下的 6 / 2，加新导入的 469 种 Poly Haven 材质） |
| 干扰物 | 杂物 193 个 | 几乎全部 | 0 | 280 / 115（几乎全是新导入的 ManiTwin 物体，外加 5 个字母牌） |
| 任务物体实例 | — | `_random` 和开放任务配置里的全部编号 | 34 个有数据任务配置里的编号 | 78 / 29：ManiTwin 碗 6 / 1（叠碗）、带把马克杯 15 / 4（挂杯；其中 11 个也给倒水），GSO 鞋 53 / 24（装箱），外加 4 个 `Geometry` 的照片、垫块、显示器 |

分层结果在 `rsi/assets/pools.json`，由 `scripts/datagen/rsi_assets.py scan` 生成：在 `5090-2` 上、官方资产加新导入资产合并后的目录里跑出，T0 937 项。按资产 id 的哈希切分，新资产加进来不会改变已有资产的归属。新资产的来源和导入方法见第三节。

推论：只靠官方资产，房间、材质、干扰物、新实例四项几乎没有可随机的空间（材质官方只剩 6 / 2 种）。要做泛化，就必须**造新资产或者从公开库导入**（第三节）。这也正是规则 1 的用意：不能拿考题来复习。

三套官方评测集本身也都属于 T0：起点直接用榜单公布的成绩（第 0 轮只抽 5 个任务各 10 个回合校准评测链路），只在最后由裁判用最好的模型完整终评一次；两个 agent 都看不到它们的逐回合结果。

### 规则 2：只能做泛化，不能押题、抄答案

- **不抄答案**：训练布局不许复用任何考场布局或官方布局里的物体位姿（同一任务、同一物体、位置差 < 2 cm 且朝向差 < 5° 视为复用）。生成器从不读评测布局的位姿，只读它的结构（有哪些物体、标签、父子关系）。
- **不押题**：数据方看不到考卷内容，只能看到按科目汇总、分档的 Score 和保留率（第四节）。每一轮数据里至少 30% 要花在**边际探索**上：沿某个泛化维度往当前还没覆盖、也没有考过的方向扩展（第三节的算子），而不是只补成绩差的那几门。
- **可审计**：每批数据都要带 `report_<任务>.json`（每个布局抽到了什么）和覆盖统计。裁判按规则 1、规则 2 逐条检查，不通过的整批作废，不进训练。

### 规则 3：两个 agent 对抗，互不通信

- **数据方**（Data Agent）负责改进生产数据；**评测方**（Exam Agent）负责改进评测。两方的目标相反：评测方要找出模型做不好的地方，数据方要让模型在没见过的考卷上做得好。
- 两方之间没有任何直接通道：不共享 worktree、运行目录、聊天记录、记忆或 Notion 页面，不读对方的文件。唯一的交互是经过**裁判**（Referee）转交的、规定格式的信息（第四节）。
- 裁判分两层。**判定层**是确定性的脚本加人工审核：算分、升降级、审计结论、成绩单的内容都由它产出，同样的输入必须给出同样的结果。**运维层**可以交给一个**裁判运维 Agent**（Referee Ops Agent）：派发和盯训练、考试、采集作业，处理故障，以及在两次运行之间维护裁判脚本。运维 Agent 不做判定。
- 判定不用 agent 的原因：裁判同时看得到 T0、考卷、训练数据和两方的全部结果，由 agent 写成绩单，措辞或侧重就可能把考卷漏给数据方；它读两方的提交时可能被夹带的文字操纵（提示词注入）；它的判断不可复现，各轮成绩就没法比较；它和两方可能是同一个模型，会有相同的偏好和盲区。

## 二、角色与权限

| | 数据方 | 评测方 | 裁判判定层（脚本 + 人） | 裁判运维 Agent |
| :-- | :-- | :-- | :-- | :-- |
| 能用的资产 | T2 训练池 | T1 考场池 + T2（考场可以包含训练分布内的题） | 全部 | 只按作业清单把资产目录链接进运行目录，不挑选资产 |
| 布局 seed 段 | 1000–4999（`split=train`） | 5000–8999（`split=val`） | 9000–9999 封存探针；0 官方 | 不生成布局 |
| 能看到 | 本方数据、本方自测结果、裁判发布的成绩单、当前模型（只能在 T2 上自测） | 本方历届考卷和逐回合结果（含视频）、当前模型 | 全部 | 作业清单、作业状态和日志、脚本解析出的结构化结果；不读两方提交里的自由文本（报告的说明字段、计划的文字部分），不看视频 |
| 看不到 | 考卷、考场资产、逐回合考试结果、官方结果 | 训练数据、数据方的方案和计划 | — | 两方的 worktree、对话和记忆 |
| 产出 | 数据集（经裁判审计）、新的 T2 资产 | 本轮考卷（布局 + 科目标注）、新的 T1 资产 | 训练后的模型、成绩单、`levels_r`、审计结论 | 作业状态、故障记录、运维日志（`referee/ops/`）；两次运行之间的裁判脚本改动（经人审阅合并） |
| 工作区 | 自己的 worktree + 运行目录 `rsi-<名>/data/` | 自己的 worktree + 运行目录 `rsi-<名>/exam/` | 运行目录 `rsi-<名>/referee/` | 自己的 worktree；运行目录 `rsi-<名>/referee/ops/` 可写，`referee/` 其余只读 |

**裁判运维 Agent 的规矩**：
- **能做的**：按裁判脚本生成的作业清单派发训练、考试、采集、导出作业，并盯到结束；作业失败（显卡冲突、显存不够、进程卡死、网络断开）时重跑，或换卡、换批大小重跑，同一个作业最多重跑 3 次；准备运行目录和资产链接；在两次运行之间写和改裁判脚本，提交给人审阅；把审计脚本标出的异常、新资产相似度检查的结果整理成报告给人看。
- **不能做的**：生成或修改成绩单、`levels_r`、审计结论、`ledger.jsonl` 里的成绩字段；往 `referee/out/data/`、`referee/out/exam/` 写任何文件；挑选或删改考试回合、训练数据（作业失败只能整作业重跑，不能只留成功的回合）；运行期间改裁判脚本、本文件或 `rsi/subjects.yaml`；和数据方、评测方通信。
- **留痕**：每次派发、重跑、换卡都在 `referee/ops/ops.jsonl` 记一行（时间、作业、动作、原因），裁判脚本据此核对：每个成绩都来自一次完整、没被挑选的作业。
- **出了判定问题找人**：脚本报错、数据和规则对不上、需要例外处理时，运维 Agent 停下来报告给人，不自己拍板。

隔离的落实方式（v0.1）：两方在 GPU 服务器上用不同的 Unix 用户，运行目录互相没有读权限；T0、T1 资产只链接进本方的 `Assets/` 覆盖目录。运维 Agent 用第三个用户，对 `referee/` 只有 `ops/` 可写，判定脚本以另一个用户运行、由人启动。两方和运维 Agent 都不能改裁判的判定脚本和本文件，要改协议得由人来改。

## 三、泛化算子（"探索边际"可以用的操作）

两方都用同一套算子，区别只在于用的资产池不同（数据方用 T2，评测方用 T1）。每个算子对应一个"科目"维度，都可以分级。

| 维度 | 算子 | 现有工具 | 需要补的 |
| :-- | :-- | :-- | :-- |
| 物体位姿 | 在任务配置的范围内重采样；把范围往外扩一级 | `scripts/datagen/x5_layouts.py` | 越界扩展要先确认专家还能解 |
| 物体实例 | 同类别换实例；造新实例（形状、尺寸、颜色、材质变体） | 平台物体登记 + `scripts/objects/SKILL.md`；运行时换色、缩放；导入 `manitwin.py instances`、`gso.py convert` | 已导入 ManiTwin 碗 7 个、带把马克杯 19 个（10-25），GSO 鞋 77 只（10-26，鞋跟朝 +x、长 0.15–0.175 m，和官方一致）；19 个杯子里 11 个验证能装下倒水任务的液体。每个新实例只换进验证过的任务（元数据 `source.tasks`，`scripts/objects/instance_fit.py` 摆成完成状态用任务自己的判定检查）。还缺：装箱的车、牙刷、锤子（`checkpoint` 要分出车头、刷头、锤头），倒水的白酒瓶（液体初始位置写死在布局里） |
| 干扰物 | 数量 0 → 5 → 10 → 20；类别；摆放密度 | `x5_layouts.py`（`clutter`）；导入 `scripts/objects/manitwin.py` | 已导入 ManiTwin 390 个（10-24）；更多可以从 ManiTwin、GSO、Objaverse-LVIS 导入 |
| 房间 | 换房间；换 `Simple_Room` 的墙面和木墙板材质（房间变体） | `x5_layouts.py`（`rooms`、`walls`：布局 `Room.appearance`，运行时由 `room_overrides.py` 重新绑定材质，世界坐标投影） | 已做（10-26）：墙面、木墙板各从本池材质里抽一种，训练池 342 种材质；`rsi_assets.audit` 会检查墙面材质。头部相机只在画面上角看到墙，和榜单 12 种彩色房间可见的范围一样 |
| 桌面 / 地面材质 | 从材质池里抽 | `x5_layouts.py`（`tables`、`grounds`）；`scripts/scenes/polyhaven_materials.py` | 已导入 Poly Haven PBR 材质 469 种（10-25）；官方 504 种里三套评测集用掉 494 种 |
| 光照 | 额外灯光的类型、数量、亮度、色温；HDR 贴图和亮度 | `x5_layouts.py`（`lights`、`background`）；`scripts/scenes/polyhaven_hdris.py` | 已导入 Poly Haven 室内 HDR 40 张（10-24）；默认亮度要调低（10-23 有过曝） |
| 相机 | 头部相机角度扰动 | `x5_layouts.py`（`camera.ori_deg`） | 不许平移：平移 2 cm 会让部分环境出图全黑 |
| 指令 | 同义改写、换说法、加无关信息 | `desc_manager` 支持多模板随机 | 各任务的 `instructions.json` |
| 恢复 | 从模型失败的状态接管，让专家演示怎么救回来（DAgger） | `scripts/datagen/collect.py` | X5 专家；从任意状态起步的接口 |

**分级**：每个维度从 L0（和官方训练数据一样）到 L3（远超训练分布）分四级，取值写在 `rsi/subjects.yaml`：每一级是一段随机方案，`python scripts/datagen/rsi_profile.py --assets Assets --pool <train|exam> --levels clutter=L2,surfaces=L1 --out p.json` 把各维度的级别合成一份方案交给 `x5_layouts.py --profile`。一个"科目" = 任务族 × 维度 × 级别；任务族也在这个文件里（12 个 `_random` 基础任务分成 7 族）。

**边际探索**：数据方每一轮至少 30% 的回合，要放在本方此前从没生成过的"维度 × 级别"组合，或者用本方新造的资产。评测方每一轮至少 30% 的考题，要放在此前从没考过的组合上。两方的探索方向都只能根据本方自己的历史来定，不能猜测对方。

## 四、信息流（裁判转交的唯一内容）

**给数据方的成绩单**（每轮一份，`referee/out/data/scorecard_r<N>.json`）：

```json
{"round": 3, "model": "OpenWAM@r3",
 "subjects": [{"axis": "clutter", "level": 2, "n": 40, "score": "20-25", "retention": "0.4-0.5"}],
 "capability": [{"task": "push_T", "n": 30, "score": "0-5"}],
 "sealed_probe": {"score": "15-20", "retention": "0.3-0.4"},
 "audit": {"accepted": true, "rejected_batches": []}}
```

成绩单按**维度 × 级别**汇总，各任务族合并，不再逐个（任务族, 维度）报：OpenWAM 推理慢，一路每小时只能考约 30 个回合（10-22 实测），逐格报每格 30 个回合，一轮就要考 1800 个回合、15 小时。只给分档的 Score（每 5 分一档）、保留率（每 0.1 一档，见下面"难度怎么调"）和回合数。不给布局、视频、资产 id、失败原因、任务族明细，也不给官方成绩。回合数少于 30 的科目不发布。

**给评测方的**：每轮新模型的推理服务地址（黑盒，只能跑本方考卷），加上本方上一轮考卷的完整逐回合结果。不给训练数据和数据方的任何信息。

**评测方交给裁判的考卷**（`exam/out/exam_r<N>/`）：布局目录（`split=val`），每个布局都标注科目（任务族、维度、级别）。考卷要满足：
- 每个维度的前沿级别至少 30 个回合（各任务族合并），五个维度都要覆盖，不许只考某一门（防偏科）；同一维度里，回合要大致平均地分到各任务族；
- 每道题都必须可解：v0.1 用布局的物理合法性检查和"不超出 `subjects.yaml` 的范围"来近似，有了 X5 专家以后改成专家能解才算。

**难度怎么调**（v0.2，按 10-24 的仿真榜单修订，原来用"成功率高于 80% 升级、低于 20% 降级"）：

- **指标用 Score，不用成功率**：用任务判据给出的 0–100 部分完成分（`_result.json` 的 `score`，和榜单排名一致）。基线模型的成功率太低：OpenWAM-α 总成功率 11.92%，泛化随机版只有 4.11%；Pi-05 分别是 6.93% 和 1.44%。成功率在这个区间，阈值判断全是噪声。
- **按每个任务自己的 L0 做锚点**：每份考卷拿 15% 的回合考 L0，也就是和官方训练数据同样的条件。每个回合的保留率 = 它的 Score ÷ 同一任务的 L0 平均 Score；某个维度在级别 k 的**保留率** ρ = 该级别各回合保留率的平均（先在任务内归一，再跨任务合并，难任务不会拖低整体）。升降级看 ρ，不看绝对分数。
- **升降规则**：
  - ρ 的 95% 置信下界 ≥ 0.7，算"已掌握"，下一轮升一级；
  - ρ 的 95% 置信上界 < 0.3，算"太难，已经没有区分度"，降一级；
  - 其余情况保持不变。每轮最多动一级，置信区间用 bootstrap 估计。
  - 0.7 和 0.3 的依据：完整的 `_random` 相当于四个维度同时开到高级别，保留率在 OpenWAM-α 上是 0.25、Pi-05 0.28、最好的纯策略 VPP2 0.40、Simate-beta 0.73；智能体系统 WorldScape-R²SI 0.84、HexaShell-Preview 0.81。所以 0.3 大约是基线模型面对完整随机时的水平，0.7 大约是目前最好的系统。
- **回合分配**：60% 放在"前沿级别"（ρ 落在 0.3–0.7 之间的最高级别），25% 放在前沿的上一级，15% 放在 L0 锚点。
- **能力缺口任务不参与调难度**：L0 平均 Score 低于 10 的任务（按榜单，OpenWAM-α 有 15 个左右，例如 `push_T`、`align_blocks`、`solve_equation`、`play_Xylophone`），说明模型连本身都不会做，谈不上泛化。这类任务只放在成绩单的 `capability` 里，每轮固定考 10 个 L0 回合（固定的同一组布局，前后轮成对比较），难度不调；把它们补上是数据方的事。

## 五、标准迭代流程（v0.3）

每一轮都按同样的步骤走、留下同样的文件、过同样的检查门。一轮的输出就是下一轮的输入，这就是"递归"：

- 模型 M_r = 用固定配方在 M_{r-1} 上训练第 r 轮通过审计的数据；
- 考卷 exam_r 由评测方根据 M_{r-1} 和本方历届结果出；
- 数据 D_r 由数据方根据第 r 轮成绩单造。

所有步骤都落成文件，任何一轮都能从文件重放、审计。级别和预算的具体数值写在 `rsi/subjects.yaml` 和运行配置里，不写在提示词里。

### 5.1 运行目录（固定结构）

```
5090-2:/data/robodojo-runs/rsi-<名>/
  config.yaml                 第 0 轮冻结的运行配置（rsi.example.yaml 的副本 + 提交号、pools.json 哈希、训练配方）
  Assets/                     官方资产 + 全部新资产的合并目录（rsi_assets.py link）；两方各自再链接一层只含本池的覆盖目录
  referee/
    ledger.jsonl              每轮一行：模型、封存探针成绩、各科目成绩、数据量、算力、是否退步
    sealed/                   封存探针布局（seed 9000–9999），第 0 轮建好后不再改
    levels_r<N>.json          第 N 轮之后每个（任务族, 维度）的当前级别
    ops/                      运维 Agent 唯一可写的地方：作业清单的执行状态、ops.jsonl（每次派发、重跑、换卡一行）
    rounds/r<N>/              考试结果、成绩单、审计报告、训练日志
    out/data/scorecard_r<N>.json   给数据方（分档）
    out/exam/results_r<N>/         给评测方（逐回合）
  exam/rounds/r<N>/           评测方：plan.json、profiles/、布局（seed 5000–8999，split=val）、manifest.json
  data/rounds/r<N>/           数据方：plan.json、profiles/、布局（seed 1000–4999，split=train）、episodes/、submission.json
dsw-4:<data_root>/rsi-<名>/   训练数据（官方 + 历轮通过审计的生成数据）和各轮模型 M_<N>
```

| R0.1 冻结配置 | 复制运行配置，记下本仓库和 XPolicyLab 的提交号、`pools.json` 的哈希、训练配方 | — | 之后整个运行不改；要改就开新的运行 |
| R0.2 资产分池 | 在合并资产上统计 T0，把其余资产切成 T2 / T1 | `rsi_assets.py scan` | T0 项数和上次一致：新资产只会让池子变大 |
| R0.3 专家就绪 | 每个范围内任务的专家在 20 个 L0 训练布局上采集一遍 | `collect.py` + `plugins/<任务>.py` | 验收率 ≥ 50% 的任务进"可生产"清单；其余记为"无专家"，数据方本运行里不能给它造演示 |
| R0.4 封存探针 | 每个范围内任务 10 个布局：L0 2 个，每个维度单独 L2 各 1 个，五个维度同时 L2 3 个；用考场池。每轮都考同一组，前后成对比较 | `rsi_profile.py`（compose）+ `x5_layouts.py` | 审计通过；保持姿态跑一遍没有不稳定的布局。建好后两方都看不到 |

### 5.3 第 r 轮（r = 1..R）：七步

| 步骤 | 谁 | 输入 | 做什么 | 输出 |
| :-- | :-- | :-- | :-- | :-- |
| 1 出卷 | 评测方 | M_{r-1} 的推理地址（黑盒）、本方历届考卷和逐回合结果、`levels_r-1` | 按回合分配规则选科目和级别（第四节），每个科目用考场池合成随机方案，生成布局 | `exam/rounds/r/`：布局 + `manifest.json`（每个布局的任务族、维度、级别） |
| 2 考试 | 裁判（判定脚本生成作业清单，运维 Agent 派发和盯作业） | exam_r、封存探针、能力缺口任务各 10 个 L0 回合 | 在 M_{r-1} 上跑 | `referee/rounds/r/` 逐回合结果 |
| 3 发成绩 | 裁判（判定脚本） | 逐回合结果 | 按科目算平均 Score、保留率 ρ 和 95% 置信区间（bootstrap），套升降规则 | 分档成绩单 → 数据方；逐回合结果和 `levels_r` → 评测方 |
| 4 定计划 | 数据方 | 成绩单 r、本方历史 | 定本轮每个（任务, 维度组合, 级别）的回合数；≥ 30% 放在本方没做过的组合；总数不超预算；只用"可生产"清单里的任务 | `data/rounds/r/plan.json` |
| 5 造数据 | 数据方 | plan | 用训练池合成随机方案 → 生成训练布局 → 专家采集 → 只留验收通过的回合 → 导出。可以在 T2 上自测 M_{r-1} | `episodes/` + `submission.json`（每批的布局目录、报告、验收统计） |
| 6 审计 | 裁判（判定脚本 + 人） | submission | 第六节清单逐条检查 | `referee/rounds/r/audit.json`；通过的批次进训练集 |
| 7 训练 | 裁判（运维 Agent 按固定配方派发） | M_{r-1}、官方数据、历轮通过审计的生成数据 | 按固定配方训练（起点、混合比例、步数都在第 0 轮定好） | M_r；ledger 第 r 行 |

步骤 1–3 和 4–5 不能并行：数据方要等成绩单。步骤 7 的同时，评测方就可以开始准备下一轮的出卷方案，但要等 M_r 出来才能定稿。

### 5.4 检查门

| 门 | 位置 | 通过条件 | 不通过怎么办 |
| :-- | :-- | :-- | :-- |
| G1 考卷 | 步骤 1 之后 | `rsi_assets.py audit --pool exam` 通过；每个维度的前沿级别 ≥ 30 回合、各任务族大致平均；L0 锚点占 15%；≥ 30% 是没考过的组合；保持姿态跑一遍没有不稳定的布局；有专家的任务，专家在抽查的布局上能做完 | 退回评测方重出，本轮不考 |
| G2 考试 | 步骤 2 之后 | 每个评测作业退出码 0，并且 `_result.json` 的 `eval_time` 等于计划回合数；`ops.jsonl` 里每个作业的重跑都是整作业重跑 | 运维 Agent 只重跑失败的作业（最多 3 次，仍失败就报告给人）；不稳定的布局另记、不计分 |
| G3 数据 | 步骤 6 | 第六节清单全过 | 整批作废，不进训练；作废原因写进审计报告，成绩单里只说"有批次作废" |
| G4 退步 | 下一轮步骤 2 | M_r 的封存探针 Score 低于历史最好模型，且差距超出置信区间，就记为退步 | 第 r+1 轮改用历史最好模型来考和接着训；成绩单标 `"regressed": true`，不说原因 |

### 5.5 什么时候停

- 跑满配置里的轮数；
- 或者连续两轮封存探针没有超出置信区间的提升（早停）；
- 或者训练、评测预算用完。

停下后，历史最好的模型在官方 seed 0、1、2 上终评，只此一次。"轮数 → 泛化"的曲线用 ledger 里的封存探针成绩画；考卷每轮都在变，考卷成绩不能跨轮比较。

### 5.6 递归的另一层：资产、算子、专家也在迭代

两方都可以在本方的池子里造新资产、补新专家，但要走准入，并且只在**下一轮开始时**生效，一轮之内池子和级别表都冻结：

- **新资产**：导入脚本 → 去重（面数、贴图、并排渲染）→ 用 `scripts/objects/instance_fit.py` 摆成完成状态、用任务自己的判定检查 → 登记 `rsi/assets/imported.json`（来源、许可证、验证过的任务）→ 裁判在下一轮 R0.2 那一步重扫分池。数据方造的进 T2，评测方造的进 T1。
- **新级别或新维度**：只能由人在两次运行之间改 `rsi/subjects.yaml`，改了就是新的运行。
- **新专家**（`scripts/datagen/plugins/<任务>.py`）：由人合并进仓库主线后生效，下一轮 R0.3 重新统计"可生产"清单。专家代码是公共的，评测方可以用它检查题目可解，但看不到数据方的计划和数据。

### 5.7 节奏

| 阶段 | 大约用时 |
| :-- | :-- |
| 出卷 + G1 | 2 小时 |
| 考试（考卷约 250 + 能力缺口约 60 + 封存探针 120 回合；OpenWAM 一路每小时约 30 回合，`5090-2` 开 4 路） | 3.5–4 小时 |

## 六、裁判的审计清单（数据进训练前必须全部通过）

1. 布局和数据里没有任何 T0、T1 资产（检查房间、材质、HDR、杂物的类别和编号、物体实例）。
2. 没有复用考场布局或官方布局里的位姿（阈值见规则 2）。
3. 布局都在数据方的 seed 段内，`split.json` 标为 train。
4. 边际探索占比 ≥ 30%，按 `report_<任务>.json` 统计。
5. 每个回合都通过任务插件的验收；按 `scripts/datagen/SKILL.md` 完成导出、审计和回放一致性检查。
6. 新资产要登记来源：数据方造的进 T2，评测方造的进 T1。由裁判比对新资产和 T0、T1 资产的相似度（v0.1 先人工看渲染图），过于相似的不收。
7. 运维日志 `referee/ops/ops.jsonl` 和作业清单对得上：每个进训练的批次、每个计分的考试作业都是完整跑完的作业，重跑都是整作业重跑，没有只挑成功回合的情况。

## 七、输入配置

复制 `rsi/rsi.example.yaml`，填好以下三部分：要迭代的模型（策略目录、checkpoint、动作类型）、训练资源（主机别名、GPU、每轮时长上限、训练命令）、评测平台（主机别名、可用 GPU、仿真环境）。文件里只写 SSH 主机别名，不写地址和凭据。
